IMPLEMENTATION REFERENCE / v0.4

A policy-driven conversion service with bounded external work.

GordonKit coordinates document engines and artifact processors. It does not implement a Word layout engine or promise identical rendering across renderer and font environments.

01

Architecture and boundaries

The framework-independent application service owns requests, results, selection, fallback, validation, and publication. CLI and FastAPI are presentation adapters; engines only probe and execute their own renderer.

Service

Stable entry point for one request, batches, and probes.

Pipeline

Composes routes, tracks warnings, validates and publishes artifacts.

Adapters

Encapsulate Word COM, LibreOffice, or optional Gotenberg details.

02

Artifact routes

SourceTargetExecution path
DOCXPDFPolicy-selected renderer, PDF validation, atomic publication.
DOCXMarkdown / HTMLDirect semantic extraction and deterministic writer.
PDFMarkdown / HTMLEmbedded-content extraction; image-only content reports an OCR need.
DOCX or PDFPage imagesValidated PDF, then PDFium/Pillow rasterization when installed.

A DOCX request that needs PDF and page images renders and validates a temporary PDF once, then rasterizes it. Markdown and HTML share one normalized extraction pass.

03

Engine selection and fallback

Probes establish availability and revision/comment capability before execution. Explicit engines and strict modes never fall back; automatic selection can proceed only to another capable engine and records an ENGINE_FALLBACK warning and reason.

Interactive Windows desktop

Word COM, LibreOffice, then Gotenberg.

Other desktop environments

LibreOffice, then Gotenberg.

Server

Gotenberg, then LibreOffice. Word COM is excluded.

Container

Configured container engine, then the alternative. Word COM is invalid.

Revision modes: final, original, markup. Comment modes: omit, appendix, markup. A request is never silently changed when an engine lacks capability.

04

Security controls

Untrusted input validation

  • Extension and optional MIME type must match the declared format.
  • Default source limit is 50 MiB; PDFs are capped at 1,000 pages.
  • DOCX validation rejects encryption, unsafe ZIP member paths, excess entries, expansion size, suspicious compression, and missing core OOXML parts.

External process safety

  • Commands execute as argument sequences with shell=False.
  • Output is captured with UTF-8 replacement and every call has a timeout.
  • Timeout cleanup terminates the process tree; engine work uses isolated temporary directories.

Operational rule: do not log document contents, credentials, customer metadata, sensitive full paths, or raw adapter tracebacks.

05

Advanced operations

Publication semantics

Engine outputs are staged, then checked for existence, non-zero size, parser validity, and positive page count. Publication creates the target exclusively unless overwrite is requested. Overwrite uses a same-directory temporary file and replace operation.

Container and remote renderers

Use the repository’s explicit Compose profiles for a LibreOffice standalone API, Gotenberg gateway, or CLI image. Gotenberg is optional: configure --gotenberg-url for the CLI or GORDON_DOC_GOTENBERG_URL for the API.

CJK reproducibility

Record renderer version and installed font set with results. Compatibility fixtures establish parseable LibreOffice output, not pixel-identical output across operating systems, renderer versions, or font inventories.

06

Private API deployment

The optional FastAPI adapter is for private deployment. It accepts DOCX bytes at /conversions, returns a PDF, and does not allow Word COM. Its default service runs in non-interactive Linux container policy.

ControlBehavior
AuthenticationOptional Bearer token uses constant-time comparison; provide a strong GORDON_DOC_API_KEY.
Resource limitsProcess-local fixed-window rate limiting and bounded conversion concurrency return 429 when exhausted.
HooksAuthentication, malware scanning, and content-free telemetry are injectable integration points.
LifecycleInput and output are staged in a temporary directory and removed after the request.

For multi-replica deployment, enforce request body limits and distributed rate limiting at ingress. See the container profile reference for launch and smoke-test commands.
