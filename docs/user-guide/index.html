01

Get started

Python 3.12 or later is required. Synchronize dependencies, then probe the platform and configured engines before the first conversion.

uv sync --dev --all-extras
uv run gordon-doc doctor

02

Convert one document

A DOCX source defaults to PDF when --to is absent. A PDF source needs an explicit target. Existing outputs are protected unless --overwrite is supplied.

DOCX to PDF

gordon-doc convert contract.docx -o contract.pdf

Require one engine

gordon-doc convert contract.docx --engine libreoffice

04

Engines and modes

Use gordon-doc engines --json to inspect engine versions and capabilities. On an interactive Windows desktop, automatic selection prefers Word COM, then LibreOffice and Gotenberg. Server mode uses Gotenberg then LibreOffice; container mode excludes Word COM. Strict modes and explicit --engine never silently switch renderers.

gordon-doc convert draft.docx --mode strict-libreoffice
gordon-doc convert draft.docx --revisions markup --comments appendix

05

Batch conversion and PDF comparison

Batch work

Each source is isolated; one failed item does not stop the others.

gordon-doc batch *.docx --output-dir converted --json

Visual comparison

Compare PDF structure, fonts, size, and rendered pixels; write differing pages to a directory.

gordon-doc compare expected.pdf actual.pdf --diff-dir differences

06

Automation

Every command supports --json. Use the stable exit code rather than parsing human-readable output: 0 success; 2 invalid input or existing output; 3 unavailable engine/capability; 4 conversion failure, timeout, or missing output; 5 PDF validation failure.

Microsoft Word and LibreOffice can produce different layouts from the same input. The result reports the selected engine and any fallback reason; it does not claim visual equivalence.
