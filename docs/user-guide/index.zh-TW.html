01

開始使用

需要 Python 3.12 以上。同步依賴後，先 probe 平台與已設定的引擎，再開始第一次轉換。

uv sync --dev --all-extras
uv run gordon-doc doctor

02

轉換一份文件

DOCX 未指定 --to 時預設輸出 PDF；PDF 來源需要明確的目標。除非加入 --overwrite，否則既有輸出會受到保護。

DOCX 轉 PDF

gordon-doc convert 合約.docx -o 合約.pdf

指定引擎

gordon-doc convert 合約.docx --engine libreoffice

03

選擇輸出產物

目標選項預設路徑
Markdown--to markdown<stem>.md
HTML--to html<stem>.html
頁面圖片--to images<stem>.pages/0001.png
PDF--to pdf<stem>.pdf
gordon-doc convert 會議記錄.docx --to markdown --to html

04

引擎與模式

使用 gordon-doc engines --json 查看引擎版本及能力。互動式 Windows desktop 的自動選擇依序為 Word COM、LibreOffice、Gotenberg；server 模式使用 Gotenberg、LibreOffice；container 模式排除 Word COM。strict mode 與明確指定的 --engine 不會靜默改用其他 renderer。

gordon-doc convert 草稿.docx --mode strict-libreofficegordon-doc convert 草稿.docx --revisions markup --comments appendix

05

批次轉換與 PDF 比較

批次作業

每個來源都被隔離處理；一個項目失敗不會停止其他項目。

gordon-doc batch *.docx --output-dir converted --json

視覺比較

比較 PDF 結構、字型、大小及渲染像素；不同頁面輸出至指定目錄。

gordon-doc compare expected.pdf actual.pdf --diff-dir differences

06

自動化

所有指令都支援 --json。應使用穩定 exit code 而不是解析人類可讀訊息：0 成功；2 輸入無效或輸出已存在；3 引擎／能力不可用；4 轉換失敗、逾時或無輸出；5 PDF 驗證失敗。

Microsoft Word 與 LibreOffice 可能對相同來源產生不同版面。結果會回報實際引擎與 fallback 原因，不宣稱視覺相等。
