ドキュメントコンバーターのアーキテクチャ

application service、engine protocol、ポリシーの orchestration、adapter、PDF 検証を含む、GordonKit の可搬なドキュメント変換アーキテクチャを理解します。

依存の流れ

ライブラリと CLI の呼び出しはどちらも application service から入ります。orchestrator がポリシーを適用してから共有の engine protocol を呼び出し、生成された PDF を検証します。

Library / CLI
  -> Application service
  -> Orchestrator and policy
  -> Engine protocol
  -> PDF validation

Adapter のルール

プラットフォーム API と subprocess はエンジン adapter の内側に留めます。Windows 専用の依存パッケージは遅延インポートされるため、コアパッケージは可搬性を保ちます。
